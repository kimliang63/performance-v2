# 审定页「等级分布」需求说明（用户视角）

> 依据原型 `prototype/perf/current/manager/demo-ratify-direct.html` 中 `#distConclusion`（左表）与 `#chartDist`（右图）的**当前实现**整理，供转交开发对齐体验与计算口径。本文不描述接口、表结构或前后端对接。

---

## 1. 背景与目标

结果审定时，管理者需要一眼看清：各绩效等级当前有多少人、相对强制分布规则是否超限、标准线在哪里、相对调整前发生了什么变化。审定页顶部的「等级分布」区块承担该职责：左侧用表格给出规则人数字符（大/小于等于）与符合结论，右侧用柱状图叠加调整前 / 当前 / 标准线，并支持 hover 读数。

目标是让审定人在调等级时持续对照同一套复合规则（多等级合计占比约束），知道「谁超了、本档应调多少、标准人数是多少」——重叠规则下按**瀑布分摊**给出每档自己的名额差，而不是把整条规则的累计差额原样贴到每一档上。

---

## 2. 页面结构

「等级分布」为独立面板（`#distOverview`），标题行右侧展示总人数 / 已到达 / 未到达统计，以及「收起 / 展开」按钮。

展开态主体为左右各半的网格（`grid-template-columns: 1fr 1fr`，约 50:50）：

| 区域 | 容器 | 内容 |
|------|------|------|
| 左 | `#distConclusion` | 「分布结论」表：等级、分布规则范围、当前、是否符合 |
| 右 | `#chartDist` | 柱状图：调整前灰柱 + 当前红/绿柱 + 标准橙虚线 |

窄屏（约 ≤980px）改为上下堆叠：表在上、图在下。下方人员筛选区不随分布卡收起而消失。

## 3. 左表 `#distConclusion`

### 3.1 列

表头固定为四块：

| 列 | 说明 |
|----|------|
| 等级 | 七档全称：远超预期、超出预期、符合预期+、符合预期、符合预期-、低于预期、远低预期 |
| 分布规则范围 | 表头用 `colspan = 规则条数` 合并；表体按规则拆成多列，单元格为**大/小于等于人数短文案**（如 `≤25`，不含「人」；非百分比、非 `低–高` 闭区间文案）；悬停 `title` 展示完整口径（百分比 + 「人」） |
| 当前 | 该等级当前人数（取审定等级；未填审定则回退考核等级） |
| 是否符合 | 绿勾，或红底仅显示**本档分摊差值**（如 `-3`、`+3`），不写「符合/不符合」文字 |

单元格整体居中；表体行高均分七档；行可点击，与右侧柱联动筛选下方名单。

### 3.2 复合规则与合并单元格

规则不是「每个等级各自一条」，而是**多等级合计占比**约束。原型当前四条：

1. 「远超预期」合计 ≤ 10%  
2. 「超出预期 + 远超预期」合计 ≤ 20%  
3. 「远超预期 + 超出预期 + 符合预期+」合计 ≤ 50%  
4. 「符合预期- + 低于预期 + 远低预期」合计 ≥ 10%  

表体规则列渲染规则：

- 某条规则覆盖的等级在表行顺序上**连续**时，用 `rowspan` 合并为一格，格内写该规则换算后的人数短文案（不含「人」）；悬停展示「不超过/不少于{P}%，小于等于/大于等于{N}人」；带 `rowspan` 的规则格左侧有蓝线标识合并范围。  
- 某等级参与了部分规则、但不在某一规则列上时，该列为空单元格。  
- **整档未参与任何规则**（原型中为「符合预期」）：四条规则列合并为一格，居中显示 `-`。

### 3.3 「是否符合」列口径（表 = 图）

左表红标 / 绿勾与右图红绿柱、标准线、hover **共用同一套「分摊差值」**：

- 分摊 Δ = 0（含无规则档）→ 绿勾 / 绿柱 / 「✅符合」  
- 分摊 Δ ≠ 0 → 红底显示带符号数字（如 `-3`、`+3`）/ 红柱 / 「需调出/调入」  

不再使用「首个不达标整规则差额」或「最严差额」贴到每一档。

## 4. 规则人数字符怎么算

### 4.1 分母与取整

分母 = 当前考核组范围内、参与分布统计的人员总数（原型：考核组筛选后的全员；默认「全部」时为 50）。  
左表展示与合规判定共用同一套取整：

| 运算符 | 换算 | 内部闭区间（用于判断开界） | 页面展示 |
|--------|------|------------------------------|----------|
| ≤ P% | `max = floor(分母 × P / 100)` | `[0, max]` | 见 4.2 |
| ≥ P% | `min = ceil(分母 × P / 100)` | `[min, 分母]` | 见 4.2 |

整规则合规：≤ 看「涉及等级人数之和 ≤ max」；≥ 看「之和 ≥ min」。整规则超限差值：≤ 为 `-(实际−max)`，≥ 为 `+(min−实际)`。该整规则差值**只作为分摊输入**，不直接写到每一档的「是否符合」。

### 4.2 展示格式（大/小于等于人数）

内部仍可按闭区间换算人数，**格内展示时**把开界省略且**不含「人」**；完整口径（含百分比与「人」）放在悬停 `title`：

| 条件 | 格内展示 | 悬停说明 |
|------|----------|----------|
| 仅上界有意义（下界为 0 或开放） | `≤{max}` | `不超过{P}%，小于等于{max}人` |
| 仅下界有意义（上界为分母或开放） | `≥{min}` | `不少于{P}%，大于等于{min}人` |
| 上下界都有意义 | `≥{min}且≤{max}` | `不少于{P1}%且不超过{P2}%，大于等于{min}人且小于等于{max}人` |
| 无规则 | `-` | — |

### 4.3 分母 50 时当前四条规则

| 规则 | 含义 | 换算 | 格内展示 | 悬停 |
|------|------|------|----------|------|
| 1 | 远超 ≤10% | floor(50×10%)=5 → 内部 0–5 | **≤5** | 不超过10%，小于等于5人 |
| 2 | 远超+超出 ≤20% | floor(50×20%)=10 → 内部 0–10 | **≤10** | 不超过20%，小于等于10人 |
| 3 | 远超+超出+符合+ ≤50% | floor(50×50%)=25 → 内部 0–25 | **≤25** | 不超过50%，小于等于25人 |
| 4 | 符合-+低于+远低 ≥10% | ceil(50×10%)=5 → 内部 5–50 | **≥5** | 不少于10%，大于等于5人 |

## 5. 重叠规则：瀑布分摊（核心口径）

### 5.1 枢轴

以「**符合预期**」为枢轴（该档本身通常无规则，分摊 Δ 恒为 0）：

| 侧 | 等级（表行自上而下） | 约束类型 | 分摊方向 |
|----|----------------------|----------|----------|
| 之上 | 远超预期 → 超出预期 → 符合预期+ | 上界 ≤（超额需调出） | **从上到下** |
| 枢轴 | 符合预期 | 无 | 始终 ✅ |
| 之下 | 符合预期- → 低于预期 → 远低预期 | 下界 ≥（缺口需调进） | **从下到上** |

### 5.2 上段（≤ 超额）怎么分

对每条 ≤ 规则，算出整规则超额人数 `overflow = max(0, 合计 − max人)`。  
按等级**从上到下**走：当走到该规则覆盖范围内的**最底档**时，把

```
本档应调出 = overflow −（该规则内更高档已分摊的调出量）
```

（若 ≤0 则本档记 0）累加到该档的分摊 Δ（记为负数）。

直观理解：窄规则先由顶档消化自己的超额；更宽规则多出来的超额，再由新纳入的下一档吸收；已被上面档位消化掉的量，不再重复记到下面档。

### 5.3 下段（≥ 缺口）怎么分

对每条 ≥ 规则，算出整规则缺口 `shortage = max(0, min人 − 合计)`。  
按等级**从下到上**走：当走到该规则覆盖范围内的**最底档**时，把

```
本档应调进 = shortage −（该规则内更低档已分摊的调进量）
```

累加到该档的分摊 Δ（记为正数）。当前原型仅一条下界规则时，缺口全部落在**远低预期**。

### 5.4 标准人数

```
标准人数 = max(0, 当前人数 + 本档分摊Δ)
```

例：当前 8、分摊 −3 → 标准 5；当前 0、分摊 +3 → 标准 3。

#### 应调出超过本档当前人数

瀑布算出本档应调出量 `x`（「是否符合」为 **−x**）时，**Δ 不按本档当前人数封顶**。即使「当前」列人数 &lt; `x`：

| 列 | 口径 |
|----|------|
| 是否符合 | 仍显示 **−x**（完整分摊差额，不改成 −当前） |
| 标准人数 | `max(0, 当前 + Δ)`，可落到 **0** |
| 实际能调几人 | 看「当前」列——本档现有多少人，最多只能调出多少人；差额只是规则压力，不虚构可调人数 |

演算例：远超当前 = 2、分摊应调出 = 5 → 「是否符合」**−5**，标准人数 **0**（`max(0, 2 + (−5))`）；本档实际最多只能调出 2 人。

调入侧（「是否符合」**+x**）若分摊量大于本档合理空间，展示同样不封顶：仍显示完整 **+x**，标准人数 = 当前 + Δ。调入不存在「本档人数不够调出」的对称问题——缺的是名额压力，不是从本档往外抽人。

### 5.5 四场景对照（「是否符合」）

展示约定（左表红底数字 / 绿勾；右图 hover 同口径）：

| 分摊 Δ | 左表「是否符合」 | 含义 |
|--------|------------------|------|
| &lt; 0 | 红底 `−N` | 本档需**调出** N 人 |
| &gt; 0 | 红底 `+N` | 本档需**调入** N 人 |
| = 0 | 绿勾 ✅ | 本档无需调整（含无规则的「符合预期」） |

以「符合预期」为枢轴，四个业务场景与**现有瀑布实现**的对应关系如下。

| # | 场景 | 触发规则类型 | 分摊方向 | 「是否符合」 | 现算法是否产生 | 数值例（分母 50） |
|---|------|--------------|----------|--------------|----------------|------------------|
| 1 | **符合预期之上 — 调出** | 上段 **≤** 规则超额：`overflow = max(0, 合计−max人)`；走到该规则覆盖的最底档时，本档 `Δ = −(overflow − 更高档已分摊调出)` | **从上到下**（远超 → 超出 → 符合+） | 红底 **−N** | ✅ 当前 mock 即此 | 远超当前 8、规则1 ≤5 → 整规则超额 3 → 本档 **−3**（标准 5）；超出再吸收规则2 余量得 **−3** |
| 2 | **符合预期之上 — 调入** | 需上段出现 **≥** 缺口（合计低于 min），且上段循环对称分摊正数 Δ | 设想仍为**从上到下** | 红底 **+N** | ❌ **当前不产生**：上段循环只处理 `op≠gte`（即 ≤），且 `d≥0` 直接跳过；原型上段三条全是 ≤ | *示意（算法未实现）*：若配置「远超+超出 ≥10人」且合计仅 6，缺口 4；从上到下落到规则底档「超出」→ **+4**。开发勿按现原型验收此场景 |
| 3 | **符合预期之下 — 调出** | 需下段出现 **≤** 超额（合计高于 max），且下段循环对称分摊负数 Δ | 设想仍为**从下到上** | 红底 **−N** | ❌ **当前不产生**：下段循环只处理 `op===gte`，且 `d≤0` 直接跳过；原型下段仅一条 ≥ | *示意（算法未实现）*：若配置「符合-+低于+远低 ≤8人」且合计 11，超额 3；从下到上落到规则底档「远低」→ **−3**。开发勿按现原型验收此场景 |
| 4 | **符合预期之下 — 调入** | 下段 **≥** 规则缺口：`shortage = max(0, min人−合计)`；走到该规则覆盖的最底档时，本档 `Δ = +(shortage − 更低档已分摊调进)` | **从下到上**（远低 → 低于 → 符合-） | 红底 **+N** | ✅ 当前 mock 即此 | 符合-/低于/远低合计 2、规则4 ≥5 → 缺口 3 → 全部落在远低 **+3**（标准 3）；符合-、低于为 ✅ |

要点（转交开发）：

1. **现状能力边界**：现规则 = 上段三条 ≤ + 下段一条 ≥；现瀑布 = 上段只消化超额为负 Δ、下段只消化缺口为正 Δ。因此线上演示只会出现场景 **1** 与 **4**（外加大量 ✅）。  
2. **场景 2 / 3**：不是「某档当前低于标准线」的二次推导——标准线本身就是 `当前+Δ`，不会反向再生成 Δ。要出现之上调入 / 之下调出，必须先有**反向运算符的规则**，再扩展瀑布两侧对称分支；在此之前 UI 统一仍按「Δ&lt;0 调出 / Δ&gt;0 调入 / 0→✅」渲染即可。  
3. **枢轴档**：符合预期永不参与分摊，恒为 ✅。

## 6. 右图 `#chartDist`

### 6.1 图层（重叠柱，非堆叠）

自下而上：

1. **调整前**：浅灰实心柱（考核结果等级人数，未按审定覆盖）；画在下层。  
2. **当前**：绿柱（本档分摊 Δ = 0）或红柱（Δ ≠ 0）；画在上层。  
3. **标准**：琥珀色虚线折线（可带小空心点），连接各等级标准人数（= 当前 + 分摊Δ）。

横轴等级名缩写为：远超 / 超出 / 符合+ / 符合 / 符合- / 低于 / 远低；纵轴从 0 起、步长 1。

### 6.2 图例（底部）

四项：`当前·符合`（绿）、`当前·不符合`（红）、`调整前`（灰）、`标准`（橙虚线）。

### 6.3 Hover 文案（四行）

指向某等级时标题为等级全称，正文固定四行：

1. `调整前：{人数}`  
2. `当前：{人数}`  
3. `标准人数：{人数}`  
4. `是否符合：`  
   - 分摊 Δ = 0 → `✅符合`  
   - 分摊 Δ &lt; 0 → `需调出{绝对值}人`  
   - 分摊 Δ &gt; 0 → `需调入{差值}人`

## 9. 配置校验（COE / 强制分布规则保存时）

配置模型：先按顺序维护等级名称 → 每条分布规则绑定连续多个等级 → 运算符 ∈ {≤, ≥, 之间} 并填比例。审定页瀑布分摊按「符合预期」为枢轴：≤ 超额产生调出（−）、≥ 缺口产生调入（+）；同向重叠规则靠瀑布消化，**不在配置侧拦截**。

保存时只拦「同一等级会被算出既要调入又要调出」及明显非法区间，不拦同向嵌套。

### 9.1 术语

| 术语 | 含义 |
|------|------|
| 枢轴 | 默认等级名「符合预期」（可配置）；该档不参与分摊，Δ 恒为 0 |
| 之上 / 之下 | 等级顺序中枢轴上方各档 / 下方各档 |
| 压力方向 | ≤ → 调出；≥ → 调入；「之间」→ 同时贡献调出与调入（单条规则内运行时超上界与欠下界互斥） |

### 9.2 拦截规则（按序校验，任一失败阻断保存）

1. **枢轴唯一且未绑定**：等级序列中须恰好一个枢轴档；枢轴档不得出现在任何规则的绑定等级中。  
2. **规则不跨枢轴**：一条规则绑定的等级须全部在枢轴之上，或全部在枢轴之下。  
3. **绑定非空且顺序连续**：绑定等级按等级表顺序须为连续一段，禁止空集、跳档。  
4. **比例合法**：≤ / ≥ 填单一比例 P，且 `0 < P ≤ 100`；「之间」填 P_min、P_max，且 `0 ≤ P_min < P_max ≤ 100`（颠倒或空区间直接拦）。  
5. **同档反向压力（核心）**：对每一非枢轴等级 G，收集所有覆盖 G 的规则的压力方向：  
   - 若覆盖 G 的规则 ≥ 2 条，且方向并集**同时含调入与调出** → 拦截（提示等级名与冲突规则名）；  
   - 若 G 仅被 **1 条「之间」** 覆盖 → 放行；  
   - 若 G 仅被同向多条（全 ≤ 或全 ≥）覆盖 → 放行（瀑布重叠）。  
6. **同向嵌套比例不得反向收紧（建议强校验）**：同侧、同运算符、绑定集合 A ⊂ B 时——均为 ≤ 则要求 `P(A) ≤ P(B)`；均为 ≥ 则要求 `P(A) ≥ P(B)`；否则该组比例在任意分母下都可能无解，拦截。  
7. **不拦截**：同向重叠/嵌套瀑布；枢轴无规则；单条「之间」；跨等级合计约束本身。

### 9.3 例子

| | 配置 | 结果 |
|--|------|------|
| 应拦截 | 「远超 ≤10%」+「远超+超出 ≥5%」 | 远超同时承调出与调入压力 |
| 应拦截 | 「远超 之间 5%–10%」+「超出预期 ≤20%」（若后者绑定含远超）或「远超 ≥3%」与「之间」叠在同档且并出反向 | 同档方向并集含调入+调出 |
| 应拦截 | 「之间」P_min=20、P_max=10；或规则绑定「符合+、符合、符合-」跨枢轴 | 空区间 / 跨枢轴 |
| 应放行（重叠瀑布） | 「远超 ≤10%」+「远超+超出 ≤20%」+「远超+超出+符合+ ≤50%」 | 同向嵌套，由瀑布从上到下分摊 |
| 应放行 | 仅「符合-+低于+远低 ≥10%」；或仅「远超 之间 5%–15%」 | 单向下界 / 单条双界互斥 |
